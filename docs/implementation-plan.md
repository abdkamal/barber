# خطة التنفيذ (المرحلة 5)

الإذن الصريح بالبرمجة: 2026-09-24. المرجع: `design.md` (المسودة 2.1) و`decisions.md` ونظام التصميم والنموذج الأولي.

## هيكل المستودع
| المسار | المحتوى |
|---|---|
| `packages/engine` | محرك الجدولة — TypeScript نقي بلا قاعدة بيانات ولا شبكة، مع اختبارات ومحاكي يوم عمل |
| `server` | السيرفر — NestJS + PostgreSQL (دليل + قاعدة لكل صالون) |
| `packages/saloni_ui` | نظام التصميم في Flutter (الألوان، الخطوط، المكونات) — مشترك بين التطبيقين |
| `packages/saloni_api` | عميل الواجهة البرمجية والنماذج في Dart — مشترك |
| `apps/customer` | تطبيق الزبون (Flutter) |
| `apps/staff` | تطبيق الطاقم: الحلاق والمدير (Flutter) |
| `infra` | Docker Compose للتطوير: PostgreSQL + PgBouncer |

## المعالم
1. **المحرك + المحاكي** (القسم 5 من التصميم).
2. **أساس السيرفر:** الدليل، عزل الصالونات، أداة الترحيل، الحسابات والأمان (القسم 7).
3. **نظام التصميم في Flutter** (`saloni_ui`).
4. **منطق السيرفر:** الحجز، الطوابير، الأحداث والمزامنة، المؤقتات، التنبيهات، التقارير، ملف الصالون والكتالوج.
5. **تطبيق الطاقم:** متصلًا، ثم الانقطاع والمزامنة.
6. **تطبيق الزبون.**
7. ربط الواجهات، الاختبارات، الفحوص الأمنية، المراجعة المستقلة (المراحل 6–10) ← نسخة تطوير لتجربة المستخدم (المرحلة 11).

## قواعد العمل
- كل معلم يُختبر قبل حفظه في Git. لا يُخفى فشل اختبار.
- لا تغيير للمتطلبات؛ أي قرار مؤثر يُرفع للمستخدم.
- بناء APK يحتاج فتح `dl.google.com` (انظر `environment.md`).
